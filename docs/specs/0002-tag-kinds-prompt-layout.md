# 0002 标签分两种、提示词可编辑、界面重排

## 背景

第一期里关键词规则和 AI 打的标签混在一张表里。AI 给每条最多打 5 个自由标签，几乎都只用一次，看板上的标签栏又长又乱。整理用的提示词写死在代码里，想调整措辞只能改代码。网页布局是顶栏 + 一长串筛选，信息多了不好找。

## 要做的

### 1. 两种标签

- **类别标签**（`label`）：由关键词规则产生，用户可控。
  - 分类关键词（如「待办=todo」）命中时，照旧打上分类名作为类别标签。
  - 新增「标签关键词」规则，每行 `关键词=标签`（如 `测试=测试`、`发票=票据`）。消息任何位置出现关键词就打上对应标签，不改分类。
- **内容标签**（`topic`）：AI 整理时根据内容生成，用于以后按主题查找。
  - 每条 1–3 个，优先复用已有的内容标签。
  - 不得与类别标签重名。
- 数据库新增迁移，给 `tags` 加 `kind` 列：
  - 已有标签若与分类名或标签关键词的标签同名，归为 `label`。
  - 其余归为 `topic`。
- 网页上两种标签分开显示，样式可区分：
  - 类别标签：实心。
  - 内容标签：描边、带 `#`。
- 条目详情页可分别编辑两种标签。

### 2. 提示词可编辑

- 设置页新增「提示词」，可编辑整理说明部分：角色、各分类含义、标签和摘要的要求。
- 以下部分由程序拼接，不开放编辑，以免改坏后解析失败：当前时间、`fixed_category` 规则、已有标签列表、输出 JSON 格式、各深度的 `detail` 要求。
- 留空或点「恢复默认」即使用内置默认文本。设置页同时展示最终发送的完整提示词预览（只读）。

### 3. 界面布局

- 桌面：左侧栏 + 右侧列表。
  - 左侧栏依次为：分类（带数量）、类别标签、内容标签（默认显示前 15 个，可展开全部）。
  - 顶部一行显示状态和「立即整理」。
- 手机：侧栏收成顶部可横滑的分类条，标签筛选折叠；底部导航为看板、搜索、设置。
- 设置页按小节分开：AI 服务商、模型、整理与规则、关键词、提示词、微信登录、用量。用左侧小节导航（手机上为顶部横滑），不再一页铺满。
- 卡片：标题、摘要、标签，以及到期和优先级。操作按钮收紧，次要操作弱化。
- 保持现有约束：
  - 无外部资源。
  - 模板内无内联脚本，符合 CSP。
  - 深浅色都可用。
  - 可用键盘操作。

## 不做

- 标签重命名、合并的管理页（后续需要再做）。
- 提示词多版本、按分类分提示词。

## 验证

- 单元测试：
  - 迁移归类。
  - 两种标签分开存取。
  - 标签关键词命中。
  - AI 标签不与类别标签重名。
  - 自定义提示词进入请求；留空回落到默认。
- 网页测试：看板和设置各小节渲染、提示词保存与恢复默认。
- 真实验收：手机和电脑浏览器各看一遍；发一条含标签关键词的消息，整理后核对两种标签。

## 结果

2026-10-01 完成。

- 标签分为类别标签和内容标签（迁移 0004），新增「标签关键词」规则；AI 每条最多 3 个内容标签，与类别标签重名的丢弃。
- 设置页可编辑整理说明，留空或「恢复默认」用内置文本，附完整提示词预览。
- 界面按确认过的原型重做：电脑端顶栏一级菜单、侧栏二级菜单、居中容器；手机端分类横滑、筛选收进底部抽屉、底部导航；设置分小节。「未整理」排在分类最前。
- 单元测试与网页测试通过；电脑和手机浏览器由用户查看确认。还没用真实微信发含标签关键词的消息核对两种标签。
- 未做：列表「⋯」菜单里的「推迟」「改截止时间」（网页暂无对应接口）；截止时间仍显示具体日期，没有改成「昨天」「今天」这类相对说法。
