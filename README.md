# Vinx 助手

单用户的微信收集箱。平时看到的链接、想到的点子、要做的事，在微信里发给一个 ClawBot 就算收下。后台定时用 AI 归类、打标签、写摘要；待办到期时 Bot 在微信里提醒；所有条目都能在网页上查看和整理。

整个程序是一个 Go 二进制、一个进程、一个 SQLite 文件，不需要公网地址，在家里的电脑或小主机上就能跑。

## 为什么做这个

微信是最顺手的输入框，但「文件传输助手」里的东西发进去就沉底了。Vinx 助手保留「发给自己」这个习惯，只改变发送对象：

- **收的时候不用想**：发出去就收下，Bot 回一句「✓ 已收：待办｜周五前交报告」。不用选分类，也不用等 AI。
- **整理交给定时任务**：每天定点批量处理，比逐条实时调用 AI 省 token。
- **待办会回来找你**：到期时在微信里提醒，回一句「完成 12」就办结。

## 功能

### 收件

- 支持文字、链接、图片、语音（使用微信的转写文字）、文件、引用回复。图片和文件从微信 CDN 下载、解密后存到本地。
- 收件和整理分开：消息先入库、先回执，打标签、抓网页、调用 AI 都在之后进行，不会拖慢收件。
- 消息带关键词时直接归类，关键词出现在消息的任何位置都算，例如「待办」「点子」「稍后看」。关键词表在网页上可以改。
- 链接会抓取网页标题、描述和正文（GitHub 仓库会抓 README），交给 AI 整理时一起使用。
- 同一条消息重复投递时不会重复入库。

### AI 整理

- 可接入任何 OpenAI 兼容接口，如 DeepSeek、OpenAI、本地模型。网页上可配置多个服务商，可以一键拉取模型列表。
- **五个分类**：待研究、稍后看、待办、点子、资料。没归类的条目先放在「未整理」里。
- **三档深度**：
  - 轻量：标题、摘要、标签。
  - 中等：再加 3 到 5 句话的摘要，并判断值不值得花时间看。
  - 深入：生成一份研究笔记，包含「是什么、同类对比、上手步骤」三节。
  - 消息里带「研究一下」「深入研究」时自动升档；网页上也可以手动点「深入研究」。
- 待办会解析出截止时间和优先级。「月底前」「下周三下午三点」这类说法会换算成具体时间。
- 默认每天 08:00 和 20:00 各整理一次，时间可以改。也可以在网页上点「立即整理」，或运行 `vinx-assistant batch`。
- 设置了每日 token 上限后，超出的条目留到下一次整理。整理失败的条目会重试，最多 3 次，原因在用量页里可以看到。
- 整理说明（AI 的角色、分类含义、标签要求）在网页上可以编辑，也可以恢复默认，并能预览实际发送的完整提示词。

### 两种标签

- **类别标签**：由关键词规则打上，完全由你控制。例如设置 `发票=票据` 后，消息里只要出现「发票」，就会打上「票据」。
- **内容标签**：由 AI 根据内容生成，每条 1 到 3 个，方便以后按主题查找。AI 会优先沿用已有的标签，也不会和类别标签重名。

### 微信里的指令与提醒

- 固定格式的指令直接执行，不调用 AI：
  - `完成 12`、`推迟 12 明天`、`改到 12 10-08 15:00`、`取消 12`：操作编号为 12 的待办。
  - `列表`：列出未完成的待办。
  - `撤销`：撤回上一次操作。
- 引用 Bot 发来的提醒，只回「完成」也可以，Bot 会认出是哪一条。
- 固定格式认不出时，交给轻量档 AI 理解，比如「材料那个做完了」。AI 拿不准时会列出候选让你确认，不会自己猜。
- 每天在设定的时间推送一份摘要，包括今天到期、明天到期、已逾期的待办，以及待研究积压。带具体时刻的待办到点时单独提醒。
- 每条指令执行后都会回复结果；`撤销` 可以回滚最近一次指令。

### 网页

- **看板**：左侧按分类和两种标签筛选；条目分「未处理」「已处理」查看；待办点一下就能完成。
- **详情**：显示原文、AI 笔记（Markdown）和附件。分类、两种标签、截止时间、优先级都可以手动改。
- **搜索**：全文检索，支持中文，可以按分类、状态、时间范围筛选。
- **设置**：服务商、三档模型、提示词、整理时间与 token 上限、关键词、网页登录与密码，以及微信扫码登录（二维码直接显示在页面上）。
- **用量**：每天的 token 消耗、消耗最多的条目、整理失败的条目。
- 电脑和手机都有专门的布局，支持深色模式。页面不引用任何外部 CDN 或字体，离线也能打开。

### 运维

- `vinx-assistant backup` 导出数据库快照和附件，服务运行中也可以执行。
- 微信登录失效时，网页上会显示提示。触发协议限流（错误码 -14）时自动暂停 1 小时，到点后自动恢复。
- 日志里的 API 密钥、`bot_token`、`context_token` 一律打码。
- 协议部分跟随腾讯官方插件 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)。运行 `make check-upstream` 可以对照上游的变化；程序收到协议之外的字段时，会在网页上提示（见 [internal/ilink/UPSTREAM.md](internal/ilink/UPSTREAM.md)）。

## 快速开始

需要 Go 1.27 或更新版本。纯 Go 编译，不需要 CGO。

    make build                    # 生成 dist/vinx-assistant
    ./dist/vinx-assistant serve   # 默认监听 0.0.0.0:3100，数据放在 ~/.local/share/vinx-assistant

然后按下面三步配置：

1. 打开 `http://<机器地址>:3100/`，进入「设置 → 微信登录」，用微信扫码，绑定 ClawBot。也可以在终端里运行 `vinx-assistant login` 扫码。
2. 在「设置 → 服务商」添加 AI 服务。以 DeepSeek 为例：名称填 `DeepSeek`，API 地址填 `https://api.deepseek.com`（程序会自动补 `/v1`），再填密钥。然后在「模型」里为三档各选一个模型，比如都用 `deepseek-chat`。
3. 在微信里给 Bot 发一句「待办：周五前交报告」，网页上就能看到这一条。点「立即整理」，就能看到 AI 整理后的结果。

建议接着在「设置 → 账号与数据 → 登录与密码」开启「需要登录」。开启后打开网页要先登录：登录页显示「登录 123456」这样一段文字，在微信里发给 Bot 就能登录；也可以另设一个密码作为备用。没开启时网页照常可用，每页顶部会提示。

## 部署

### 命令与参数

    vinx-assistant serve     # 常驻运行：收消息、定时整理、提醒、网页
    vinx-assistant login     # 在终端扫码登录
    vinx-assistant batch     # 立即整理一次（服务运行中也可以，不会重复整理）
    vinx-assistant backup    # 导出数据库快照和附件
    vinx-assistant password  # 设置或重置网页密码（--stdin 从标准输入读一行，--clear 清除，--no-login 关闭「需要登录」）
    vinx-assistant version

| 参数 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `--data` | `VINX_DATA` | `~/.local/share/vinx-assistant` | 数据目录 |
| `--listen` | `VINX_LISTEN` | `0.0.0.0:3100` | 网页监听地址 |
| `--base-path` | `VINX_BASE_PATH` | 空 | 挂在反向代理子路径下时的前缀，如 `/todo` |
| — | `VINX_ALLOWED_HOSTS` | 空 | 用域名访问时允许的 Host，逗号分隔 |

其他设置都在网页上改。需要代理时，设置标准的 `HTTPS_PROXY` 环境变量即可。

### systemd

仓库里有一个用户级单元模板 [deploy/vinx-assistant.service](deploy/vinx-assistant.service)：

    install -m 755 dist/vinx-assistant ~/.local/bin/
    install -m 644 deploy/vinx-assistant.service ~/.config/systemd/user/
    systemctl --user daemon-reload && systemctl --user enable --now vinx-assistant
    loginctl enable-linger "$USER"     # 未登录时也常驻
    journalctl --user -u vinx-assistant -f

迁移到其他机器时，只需拷贝二进制和数据目录。交叉编译用 `GOOS`、`GOARCH` 指定目标平台即可。

### 反向代理与域名

- **子路径**：设置 `--base-path /todo` 后，所有页面地址都带这个前缀。反向代理不要去掉前缀，原样转发 `/todo/...` 即可。访问 `/todo` 会被 308 重定向到 `/todo/`。
- **域名**：为了防止 DNS rebinding，网页默认只接受 `localhost`、回环地址和本机网卡 IP 作为 Host。用域名访问时（如 Tailscale MagicDNS），需要把域名写进 `VINX_ALLOWED_HOSTS`。
- **HTTPS 与登录 cookie**：程序只信任从回环地址连进来的代理发的 `X-Forwarded-Proto`。代理不在本机时，登录 cookie 不带 `Secure`，一旦用 http 访问同一域名，会话令牌就会明文发出。建议代理与程序放在同一台机器，或者经 HTTPS 直连。

## 安全须知

- **请开启「需要登录」**。没开启时，任何能访问这个端口的人都能查看、修改全部条目和设置。开启后，除登录页、静态文件和 `/healthz` 外都要先登录，登录保持 30 天。
- 登录方式有两种：
  - 微信验证码（主要方式）：只有你自己的微信能给绑定的 ClawBot 发消息，所以能确认身份。要发的是「登录 123456」这样的完整文字；验证码 2 分钟内有效，只能用一次，并且只有打开这个登录页的浏览器能用它换取登录。Bot 确认时会说明是哪个浏览器、从哪个地址登录的。只发你自己屏幕上的验证码；别人让你转发的验证码不要发。万一发错了，在微信里发「退出网页登录」，全部网页登录立即失效。
  - 密码（备用方式）：只以 PBKDF2-SHA256 加盐哈希保存。15 分钟内输错 10 次，会暂停密码登录 15 分钟。
- 数据库里只存会话令牌和验证码的哈希。
- 这只是最基本的一道门，没有两步验证。仍建议只在可信网络里开放，例如家庭局域网、Tailscale；经公网访问时放在 HTTPS 反向代理后面，并用 `--listen 127.0.0.1:3100` 只让代理连进来。代理和程序在同一台机器、经回环地址连接时，程序才信任代理发来的 `X-Forwarded-Proto: https`，给登录 cookie 加上 `Secure`。
- 忘记密码或怀疑泄露：在服务器上运行 `vinx-assistant password` 重置（服务运行中也可以），所有设备的登录随即失效。`--clear` 清除密码；如果这时微信也不可用，会同时关闭「需要登录」，免得进不去。`--no-login` 只关闭「需要登录」。
- 程序会拒绝跨站提交（包括登录表单）。
- 数据目录和 `backup` 导出的压缩包里有微信登录凭证（`bot_token`），请保持私有（目录权限 700），不要上传或分享。
- API 密钥保存在数据库里，网页上只显示末尾几位。修改 API 地址时必须重新填写密钥，防止密钥被发到别的地址。

## 已知限制

这些限制来自 ClawBot 协议本身：

- 不能在微信里把聊天「转发」给 Bot，只能复制内容或分享链接。
- 图片是微信压缩后的版本，不是原图。
- Bot 只能在你最近发过消息后回复。所以提醒发不出去时，会在你下一次发消息时随回执一起补发。如果你一整天都没给 Bot 发消息，当天的提醒就会推迟。
- 一个微信号只能绑定一个 ClawBot。
